# Debugging improvements

Approved scope, 17 October 2026:

1. Linked failure timeline. Identity-scoped request/response/body links and explicit trace identifiers are recorded relationships. Nearby clicks and errors are temporal context, never inferred causes. Accessible in the notebook and evidence CLI.
2. Agent-readable local evidence CLI. Read reviewed portable exports, inspect requests, events, stacks and reviewed images, list incidents and compare captures. No implicit access to the private notebook or external filing.
3. Failure-first evidence selection. Keep valid structured JSON within a byte budget, prioritize failures and their request/context, and disclose omitted IDs and fields. Preserve the original evidence for targeted queries.
4. Version-matched source maps. Read local maps and source only from the captured build commit; reject unsafe paths, malformed mappings and build mismatches. Report unresolved frames explicitly.
5. Reproduce, fix and verify. Export an incident handoff for agent-browser/Playwright and import before/after results with HAR, trace and profile attachments. Verify the same explicit failure condition, retain provenance, and never claim an automated fix from an attachment alone.

Implementation and acceptance evidence are recorded here as each item is completed. Public release and production filing remain separate from local tests.

## Use the five features

- **Timeline:** open a capture, choose Evidence → Timeline and select a failure. Recorded request links include response/body/completion artifacts. A matching configured-log finding is accessible in the linked details. Nearby clicks/exceptions remain explicitly temporal.
- **Agent interface:** `native-browser-lens evidence EXPORT_FOLDER inspect|timeline|requests|event|finding|stack|image|verification [ID]`. `list EXPORTS_DIRECTORY` lists up to 500 child exports; `compare OTHER_EXPORT_FOLDER` shows both builds/failures without asserting a fix. `image` returns only an exported reviewed PNG and checksum. No raw notebook database or network access is exposed.
- **Evidence selection:** check captures in Review for AI, choose Preview evidence selection, inspect omissions and then confirm the review. Selection uses a 32000-byte structured notebook budget, prioritizing failures and request/action context, with at most 160 events. Local findings use a separate 26000-byte structured budget. Original evidence is unchanged and queryable through the export CLI. The full reporter text remains saved when the prompt preview shortens it.
- **Source maps:** local investigation resolves CDP stack frames through version-3 mappings, inline base64 maps and inline indexed sections. Generated scripts/maps must exist uniquely in the captured commit. Current dirty files cannot substitute for that commit. Unsafe/secret paths, malformed maps, absent commits, remote maps and ambiguous scripts produce coverage findings. The build label is captured evidence; deployed script bytes are not independently verified. Maps referenced only by HTTP headers are not fetched. The decoder follows [ECMA-426](https://tc39.es/ecma426/).
- **Reproduce and verify:** select an HTTP failure and explicitly supply the success status in Diagnostics → Create reproduction handoff. The exported README explains how an agent fills `handoff.json`, runs `node reproduce.mjs before --reviewed`, fixes the application and runs `after --reviewed` from a workspace with Playwright installed. Import each result.json. The importer checks associated HAR/ZIP/profile bytes; comparison requires identical condition, steps and runner hashes and completed 503→expected-status assertions. Other failure types need a manually authored regression test. Authentication setup is specific to the agent's isolated browser; no browser credentials are copied by Lens.

## Diagnostics and privacy

HAR normalization keeps at most the first 1000 entries from the capture's exact origin, with metadata and sanitized headers. Cookies and request/response bodies are excluded; secret query parameters are redacted. Imported session/document identity is explicitly unverified. Trace ZIPs are never extracted or executed by Lens; profiles are JSON data. Original raw diagnostics stay local until the user opens/reviews each attachment for export/filing. Reviewed files are checksum checked, included in portable exports, copied safely on import with review reset, and retained through backup/restore. Cloud input excludes raw artifact paths and bytes. Review raw traces/HARs separately: image masks cannot redact them.

Agent-browser's [HAR, trace and profiler commands](https://agent-browser.dev/commands) produce the supported diagnostic formats. These imports complement its active debugging workflow; they do not establish better diagnosis accuracy or time-to-fix.
